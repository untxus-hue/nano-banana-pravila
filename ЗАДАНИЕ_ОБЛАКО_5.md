# Задание для облачной сессии 5: конвертация в правила завода (шаг 5)

Ты прораб. Работаешь в корне репозитория. Пути вида /root/БАЗА_ПРАВИЛ/исходники_кандидаты/сырьё/google/… читать как пути от корня репозитория. В интернет не ходить. Ничего не менять в сведение/исправлено/, сведение/сшито/, сведение/темы/, сведение/проверка/, сведение/поперёк/. Результаты только в сведение/правила/.

Порядок:
1. Прочитать сведение/ТЗ_КОНВЕРТАЦИЯ.md (главное, включая ЛИНИИ КООРДИНАТОРА), сведение/ТЗ_СШИВКА.md (канон полей ядра), сведение/ТЗ_СВЕДЕНИЕ.md (классы, модели), сведение/исправлено/ОТЧЁТ_ПРАВОК.md (раздел «Общий итог»).
2. Посчитать скриптом по каждой теме число ядер к конвертации (слой промпт, действует ≠ false, дом здесь или исключение из ТЗ). Ожидаемо около 290 на все темы, из них большинство в промптинг, рефы, стиль, редактирование, камера_свет_композиция, текст_в_кадре.
3. Партия 1 (6 субагентов Opus, по одному на тему): промптинг, рефы, редактирование, стиль, камера_свет_композиция, текст_в_кадре.
4. Партия 2: остальные 11 тем, объединив мелкие: субагент А — мультиход + форматы_разрешение; субагент Б — модели_сравнение + grounding + thinking + продукт_ui + api_код + безопасность_водяной_знак + лимиты_квоты + цены + другое (в каждой по 0–7 ядер; у тем без ядер к конвертации всё равно создать <тема>_пропущено.json). Каждая тема — свой файл выхода.
5. После каждого файла: свой скрипт проверки (всё из САМОПРОВЕРКИ ТЗ_КОНВЕРТАЦИЯ: нет кириллицы и хеджа, формулы дословно против цитат, каждое ядро либо в записях, либо в пропущено), при ошибке вернуть субагенту; затем git add + commit «правила: <тема>» + push сразу.
6. После всех партий — субагент-контролёр (Opus): прочитать все сведение/правила/*.jsonl и проверить сквозь темы: одно понятие — одна запись (дубли по смыслу между темами: перечислить пары, не удалять); термины употребляются одинаково; формулы совпадают с цитатами; content_en везде класс, а не случай, без хеджа. Результат — сведение/правила/КОНТРОЛЬ.json (пары дублей, замечания по записям с кодами и предложением). Не править записи.
7. сведение/правила/ОТЧЁТ_КОНВЕРТАЦИИ.md дописывать после каждой партии; в конце общий итог: записей всего, по unit_kind, по strength, derived, спор, пропущено по причинам, итоги контролёра, вопросы одним списком.

Правила субагентам: модель Opus; ничего не выдумывать: текст правила только из ядра и его цитат; непонятно — вопрос в отчёт; скрипты только во временной папке; результат на диск сразу; каждый файл коммитить и пушить сразу после проверки.
