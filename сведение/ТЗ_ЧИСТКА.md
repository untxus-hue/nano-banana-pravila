# ТЗ на чистку правил по итогам контролёра (шаг 5б)

ЗАДАЧА: довести 290 записей сведение/правила/*.jsonl до состояния «одно понятие — одна запись, текст — класс без хеджа и мета», по файлу сведение/правила/КОНТРОЛЬ.json и ТЗ_КОНВЕРТАЦИЯ.md. Файлы сведение/правила/ не менять. Без интернета. Ничего не выдумывать.

ВХОД: сведение/правила/<тема>.jsonl, сведение/правила/КОНТРОЛЬ.json (дубли, термины, формулы, замечания), сведение/правила/ОТЧЁТ_КОНВЕРТАЦИИ.md, сведение/ТЗ_КОНВЕРТАЦИЯ.md; при сомнении — сведение/исправлено/<тема>.json и извлечение/страницы/стр_<стр>.json.

ВЫХОД (папка сведение/правила_чисто/):
- Этап 1, по темам: <тема>.jsonl — те же записи той же формы после правок Ч2–Ч4, Ч6 (id сохраняются).
- Этап 2, общий: ПРАВИЛА.jsonl — все темы в одном файле после Ч1, Ч5, Ч7; ТЕРМИНЫ.json — единый словарь слоя промпт; ЖУРНАЛ_ЧИСТКИ.json — каждая правка {id, поле, было, стало, основание: код замечания КОНТРОЛЬ или номер линии, решение}; ОТЧЁТ_ЧИСТКИ.md.

ЛИНИИ:
Ч1. Дубли (К-ДУБЛЬ). Полный дубль → одна запись; остаётся та, чей дом предложен контролёром; у оставшейся поле ядра = список всех ядер, паспорт.источники = объединение, examples = объединение (без повторов). Удалённый id → в журнал с «слито_в». «Один шире» → остаётся широкая; из узкой берётся то, чего нет в широкой (оговорка, пример), в журнал. Частичное пересечение → обе записи остаются, у каждой поле связи: [id другой] с пометкой «partial overlap»; не сливать. Сила при слиянии: по слабейшей версии, если у Google нет явных слов силы для более сильной. Прямое противоречие двух записей (например место метки стиля) → обе остаются, в паспорт.статус «спор», в caveats обеих короткое «disputed: …».
Ч2. Мета в content_en (К-МЕТА): фразы о документации, о «не подтверждено», о работе разработчиков, названия страниц — убрать. Если после уборки утверждения не остаётся — запись удалить (журнал) или, если есть содержательная часть, перевести её в caveat другой записи по связи.
Ч3. Хедж (К-ХЕДЖ) → утверждение, если цитата даёт основание, иначе перенести в caveat как «Google notes: …» дословно. Даты (К-ДАТА) → в паспорт.примечание. Конкретный предмет вместо класса (К-СЛУЧАЙ) → класс; предмет — в forbids_in_output_en. Запрет в порождающей позиции (К-НЕГАТИВ) → позитивная форма, если правило не про явное исключение как у Google. Метка слота вне формулы (К-СЛОТ) → убрать по К4.
Ч4. Формулы (К-ФОРМУЛА): текст формулы Google — дословно, включая слова внутри цитаты вроде might (правило «без хеджа» относится к нашему тексту, не к тексту Google в формуле); фрагменты, которых нет в цитате, а есть только в заметке извлекателя, — из формулы убрать, в caveat с пометкой derived. Хвосты кода (комментарии, TODO) не входят в формулу.
Ч5. Термины (К-ТЕРМИН): единый ТЕРМИНЫ.json {термин, значение_en (определение, не цитата), синонимы, омонимы: [{смысл, где_употребляется}], записи: [id]}. Одно слово — одно значение; омонимы (system instructions, negative prompt, blank canvas, format, context, caption, mask) разнести на разные термины с уточняющим словом в скобках, и в записях употреблять уточнённый термин. composition — по К5 ТЗ_КОНВЕРТАЦИЯ. В записях terms заменить цитаты определениями из ТЕРМИНЫ.json.
Ч6. caveats_en: мета («not stated», «not named», «derived from examples») → в паспорт.примечание; в caveats остаются только содержательные оговорки для генератора.
Ч7. id не перенумеровывать. Итоговый ПРАВИЛА.jsonl отсортировать по теме и id. В каждой записи добавить поле версия: "2026-09-25-чисто".
Ч8. К-ПРОЧЕЕ: по предложению контролёра, если оно не выдумывает; иначе вопрос.

САМОПРОВЕРКА скриптом: всё из ТЗ_КОНВЕРТАЦИЯ (кириллица, хедж, формулы против цитат, модели, источники); нет двух записей с одинаковым title_en или content_en; каждое замечание и каждая пара дублей из КОНТРОЛЬ.json имеет запись в журнале (применено/отклонено с причиной); все id из сведение/правила либо в ПРАВИЛА.jsonl, либо в журнале как слитые/удалённые; каждый термин из terms записей есть в ТЕРМИНЫ.json.
ОТЧЁТ прорабу (кратко, по-русски): записей было / стало, слито, удалено, правок по кодам, терминов, вопросы.
