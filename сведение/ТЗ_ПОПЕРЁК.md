# ТЗ на проход поперёк тем (шаг 3)

ЗАДАЧА: 17 сшитых тем лежат в сведение/сшито/<тема>.json (канон полей — сведение/ТЗ_СШИВКА.md; правила решения противоречий а–ж и ключи моделей — сведение/ТЗ_СВЕДЕНИЕ.md, прочитать оба). Темы делались независимо, поэтому между ними есть повторы, расхождения, ссылки по старым кодам и споры, которые другая тема уже закрыла. Нужно пройти поперёк всех тем и собрать сводные файлы. Файлы тем НЕ редактировать: все предложения изменений писать отдельным файлом. Без интернета. Ничего не выдумывать: каждое утверждение в сводных файлах опирается на коды ядер (Я-…) и коды единиц (E-…); полные цитаты при сомнении — в извлечение/страницы/стр_<стр>.json.

ОБЯЗАТЕЛЬНО ПРОЧИТАТЬ сведение/сшито/ОТЧЁТ_СШИВКИ.md: разделы «Споры (29)», «Решения координатора» (приняты, менять не надо), «Общие сомнения — решать на шаге 3» и «Сомнения субагентов по темам». Каждое общее сомнение и каждое сомнение субагента разобрать: либо закрыть данными (в реестр_споров или предложения_статусов с кодами), либо занести в вопросы_все.json с классом.

ВЫХОД, папка сведение/поперёк/ (все файлы валидный JSON, тексты для базы по-английски в полях _en, служебное по-русски):

1. таблица_моделей.json — единая таблица моделей и идентификаторов: для каждой модели (pro, nb2, lite, nb25, а также other по отдельности: Imagen, 2.0 flash image и т.п.) — официальное имя, API-ID (все варианты и алиасы: preview/GA, Vertex/Gemini API), даты (анонс, preview, GA, deprecation/выключение), где доступна (Gemini API, Vertex, AI Studio, Gemini app, Workspace, Flow, Whisk, NotebookLM, Search, Photos…), базовые характеристики (вход/выход, разрешения, лимит рефов, thinking, grounding, водяной знак) — каждое значение с кодами ядер и E-кодами и с пометкой темы-источника. Расхождения между темами решать по а–ж; нерешаемое — обе версии со статусом спор.
2. реестр_споров.json — все ядра со статусом спор из всех тем + противоречия МЕЖДУ темами (одно утверждение в двух темах с разным содержанием: например число рефов в рефы против лимиты_квоты, разрешения в форматы против api_код, цены против лимиты). Для каждого: суть, версии с кодами, что говорят другие темы (коды), попытка решения по а–ж с указанием правила, итог: «решено: …» или «остаётся спор» с пометкой, чем закрывается (живой замер на заводе / решение Димы / нет данных у Google).
3. предложения_статусов.json — список предлагаемых правок в ядрах тем (код ядра, поле, было, предлагается, основание с кодами). Сюда идут: споры, закрытые данными другой темы; ядра, которые надо пометить действует:false из-за более новых данных другой темы; ошибки моделей. Не применять, только предлагать.
4. словарь_терминов.json — единый словарь из всех тем: термин, значение_en, коды, темы. Один термин — одно значение; если темы дали разные значения одному термину и это разные понятия, разнести на два термина с пометкой; если одно понятие названо по-разному, объединить и указать синонимы. Конфликты — в отдельный список.
5. связи_между_темами.json — все связи_с_другими_темами из тем, переведённые на новые коды через карта_кодов целевой темы (старый код → новый). Неразрешённые ссылки — отдельным списком с причиной.
6. дубли_между_темами.json — ядра, которые говорят об одном и том же в двух и более темах (сравнивать по смыслу и по пересечению E-кодов). Для каждой группы: коды, предлагаемая «домашняя» тема (одно понятие — один дом) и что оставить в других темах как связь. Не применять.
7. google_не_говорит.json — сводный список того, чего у Google нет: из сведение/вход/НЕ_СКАЗАНО_все.jsonl (1 129 записей из извлечения, поля: стр, url, текст) и из вопросов тем. Сгруппировать по темам, слить повторы, у каждой записи — с каких страниц это ожидалось и не нашлось. Отдельно пометить то, что на самом деле сказано в другой теме (с кодом ядра) — такие записи не «не говорит», а «сказано в теме X».
8. вопросы_все.json — все вопросы из всех тем (поле вопросы), слитые по смыслу, каждый с классом: снят (ответ есть в другой теме — код и цитата) / решение_Димы (вопрос выбора, не факта) / живой_замер (проверяется только генерацией на заводе) / остаётся (у Google нет данных). Для «снят» дать ответ.
9. СВОДКА_ПОПЕРЁК.md — 20–40 строк по-русски: самые важные расхождения между темами, сколько споров закрыто и чем, что требует решения Димы, что требует живого замера.

САМОПРОВЕРКА скриптом: JSON валиден; каждый код ядра, упомянутый в сводных файлах, существует в соответствующей теме; каждый E-код существует в источниках тем или в извлечение/страницы; в предложения_статусов у каждой правки есть основание с кодами; ни одного спора из тем не пропущено в реестре.
