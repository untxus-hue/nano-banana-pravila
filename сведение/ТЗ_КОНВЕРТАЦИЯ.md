# ТЗ на конвертацию ядер в правила завода (шаг 5)

ЗАДАЧА: из исправленной темы сведение/исправлено/<тема>.json сделать записи в форме базы правил завода. Берутся ТОЛЬКО ядра слоя "промпт" (то, что нужно переводчику промптов), с действует ≠ false и с домом в этой теме (дом.тема == <тема>). ИСКЛЮЧЕНИЕ: если дом ядра в другой теме, но там домашнее ядро не в слое "промпт", не действует или не найдено — конвертировать здесь, в паспорт.примечание написать «home core <код> is not a prompt-layer rule; converted here». Слои "инструкция" и "справка" в базу не идут (остаются в репозитории). Ничего не выдумывать: текст правила — только то, что есть в ядре и его цитатах. Без интернета. Файлы в сведение/исправлено/ не менять.

ВХОД: сведение/исправлено/<тема>.json; при сомнении в формулировке — полные цитаты в извлечение/страницы/стр_<стр>.json; определения классов — сведение/ТЗ_СВЕДЕНИЕ.md; канон полей ядра — сведение/ТЗ_СШИВКА.md.

ВЫХОД: сведение/правила/<тема>.jsonl — одна запись на строку, поля:
- id: "П-<тема>-<n>" (n с 1); ядро: код ядра; тема; подтема.
- title_en: 3–8 слов, суть правила (не «Rule about…», а само утверждение кратко).
- content_en: текст правила для генератора. Требования формы (памятка завода): класс, а не случай (обезличено: не «the cake in the example», а «the subject»); настоящее время; без хеджа (нет maybe / probably / perhaps / might / seems / likely / it is possible / in some cases); сухой текст без ссылок на источники, дат и слов «Google says»; позитивная форма в порождающей позиции (что делать, а не список запрещённого; если правило Google само про исключение вроде «No text», это допустимо как явное исключение); формулы и шаблоны Google — дословно, слоты как у Google, ничего не добавлять; составное правило — одна запись, части нумерованными строками, не резать; одно понятие — один термин (термины из словаря темы).
- unit_kind: класс ядра как есть (правило_промпта | формула_шаблон | ограничение_модели | возможность_модели | процедура | факт_лимит | …).
- strength: факт | возможность | рекомендация | требование. derived: true если статус ядра «выведено».
- target_engine: "nano_banana"; models: список ключей моделей со значением «да» (pro, nb2, lite, nb25); models_partial: ключи с «частично» и текст различия по-английски.
- modality: "image".
- applies_when_en: когда правило включается (из ситуация_в_промпте и применимости; обезличено). not_applies_when_en: из не_применяется_когда. Если в ядре пусто — "" (не придумывать).
- needs_from_prompt_en: что правило требует от задачи (например «a reference image», «the exact text string») — только если это следует из ядра; иначе [].
- forbids_in_output_en: список слов/фраз, которые НЕ должны утечь в промпт из этого правила (при магнит true: конкретные предметы из примеров, перечни артефактов, отрицательные списки — из магнит_причина и оговорок); иначе [].
- caveats_en: оговорки ядра (текст_en, модели), без хеджа, каждая одной строкой.
- examples: примеры Google дословно — только те, что несут правило (примеры.текст, код, модели, что_показывает_en). Не более 5.
- canaries_en: 1–3 короткие фразы задачи, при которых правило обязано сработать (для проверки поиска базы); только если applies_when непустой.
- terms: термины ядра (термин, значение_en).
- паспорт: {источники: [{код, стр, url, заголовок, дата, ранг, роль}], лучший_источник, дата_последняя, статус, магнит, связи: [коды ядер], дом: {тема, код}, примечание}.

ЛИНИИ КООРДИНАТОРА (ответы на сквозные вопросы отчёта правок; применять при конвертации):
К1. models у записи = модели, к которым запись относится: для ограничение_модели — те, кого ограничение касается; для возможность_модели — те, кто поддерживает; для правил и формул — те, для кого правило сказано. Значение берётся из ядра как есть (там «да» = «относится»).
К2. forbids_in_output_en: только отрицательные списки, перечни дефектов/артефактов и конкретные предметы, стоящие в самом тексте ядра или оговорок. Предметы внутри поля «примеры» не считаются: примеры лежат отдельно и в промпт не копируются.
К3. Сила выведенных правил (derived): «рекомендация» только если страница-источник подаёт пример как совет (best practices, tips, «try», «for best results»); иначе «возможность». Пограничные слова: make sure / you need to / requires / required / must → «требование».
К4. Метки слотов [Subject], [Action] и т.п. в content_en появляются только внутри формул Google (unit_kind формула_шаблон). В обычных правилах слоты не пишутся; caveat «slot labels are template notation, not prompt text» ставится у формул.
К5. Термин «composition»: Google не разводит «кадрирование» и «расстановка элементов»; в content_en использовать слово Google без расшифровки, в terms дать оба прочтения с пометкой «Google does not distinguish».
К6. Термины с пустым значением не переносить в terms. Страница ai.google/prompts (ранг 5) — только как пример, не как формулирующий источник.
К7. Статусы ядер (согласовано / один_источник / решено_по_правилу) переносятся в паспорт как есть; на content_en не влияют.

ЧТО НЕ КОНВЕРТИРОВАТЬ и куда записать: ядра слоя инструкция/справка, ядра с действует:false, ядра с домом в другой теме — в сведение/правила/<тема>_пропущено.json с причиной по каждому коду. Спорные ядра (статус спор) конвертируются с strength по слабейшей версии и caveat «disputed: …» (обе версии кратко), паспорт.статус «спор».

САМОПРОВЕРКА скриптом: JSONL валиден; id уникальны; каждое ядро слоя промпт с домом здесь и действует≠false имеет ровно одну запись, остальные — в пропущено; в полях *_en и title_en/content_en нет кириллицы; в content_en нет слов хеджа (список выше) и нет «Google», «according to», «the docs», «page», дат; у записей unit_kind формула_шаблон content_en содержит формулу дословно из цитаты источника (сверить с извлечение/страницы); models непустой или models_partial непустой или примечание почему; паспорт.источники непустой.
ОТЧЁТ прорабу (кратко, по-русски): записей, пропущено по причинам, по unit_kind, по strength, сколько derived, сколько спор, вопросы.
