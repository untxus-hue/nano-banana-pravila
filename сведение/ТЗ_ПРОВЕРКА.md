# ТЗ на проверку смысла сшитой темы (шаг 4)

ЗАДАЧА: независимая проверка одной сшитой темы сведение/сшито/<тема>.json. Ты не автор, ты проверяющий: ищешь выдумки, натяжки, неверные слияния, неверные модели, неверную силу, пропущенные магниты, кривые переводы и неверно решённые споры. Ничего в файле темы не менять: результат — отдельный файл отчёта. Без интернета. Прочитать перед началом: сведение/ТЗ_СВЕДЕНИЕ.md (правила а–ж, модели, классы) и сведение/ТЗ_СШИВКА.md (канон полей).

ВХОД: сведение/сшито/<тема>.json (ядра); полные цитаты единиц — извлечение/страницы/стр_<стр>.json (единица по коду E-<стр>-<n>: поля утверждение_en, цитата, модели, дата, раздел); части до сшивки — сведение/темы/<тема>__чN.json или <тема>.json (для проверки слияний и переводов); ядра «другого», ушедшие в тему — сведение/темы/другое.json.

ПРОВЕРИТЬ КАЖДОЕ ЯДРО, без выборки:
1. Трассировка: открыть полные цитаты всех источников ядра и решить, следует ли ядро_en из них. Вердикт: подтверждено / частично (что именно не подкреплено) / не_подтверждено (цитаты о другом) / выдумано (ни одна цитата не поддерживает). Отдельно проверить оговорки, приёмы, части составного, модели_различия — каждый пункт с кодами: подкреплён ли своими кодами.
2. Модели: значения модели {pro,nb2,lite,nb25,other,не_указано} против моделей единиц-источников и страниц. Приписана ли модель, которой в источниках нет; не пропущена ли модель, о которой источники говорят. Проверить разрешение_моделей на соответствие правилам ТЗ_СВЕДЕНИЕ (не гадать).
3. Сила и класс: «требование» только при явном must / never / only / required / do not в тексте Google; «рекомендация» при should / try / consider / we recommend / best results; «факт» при утверждении; «возможность» при can / supports / lets you. Класс по определению ТЗ. Отметить завышения и занижения.
4. Магнит: ядро, оговорка или пример, где в порождающей позиции стоит список запрещённых слов, отрицание «не пиши X», перечень артефактов (руки, зубы, текст) — должен иметь магнит true с причиной. Отметить пропуски и лишние флаги.
5. Слияния: для каждой записи в слито открыть старые ядра в частях и решить, было ли это одно утверждение для тех же моделей и той же применимости. Продукт и API слиты — ошибка (правило ж). Разные модели слиты без дословного совпадения — ошибка.
6. Споры и решено_по_правилу: проверить, что правило применено по порядку а–ж и в нужную сторону; для споров — что действительно ни одно правило не решает. Если решение есть — написать какое и чем доказано.
7. Переводы: оговорки и приёмы, переведённые с русского (в частях были поля текст без _en), сравнить с оригиналом в части: смысл сохранён? Отметить потери и добавления.
8. Формулы (класс формула_шаблон): текст дословно совпадает с источником, слоты как у Google.
9. Не_сведено: причины верны? «Слова не Google» — действительно цитата партнёра; «дубль» — действительно есть в ядрах (указать код).
10. Полнота: есть ли в частях содержимое (ядра, оговорки, примеры), которое в сшитой теме пропало не через слито и не через не_сведено.

ВЫХОД: сведение/проверка/<тема>.json:
{тема, проверено_ядер, вердикты: [{код, трассировка: подтверждено|частично|не_подтверждено|выдумано, проблемы: [{вид: трассировка|модели|сила|класс|магнит|слияние|спор|перевод|формула|полнота, что: строка, доказательство: цитата или коды, предложение: как исправить}]}], слияния: [{новый, вердикт, пояснение}], споры: [{код, вердикт, пояснение}], не_сведено: [{код_или_единица, вердикт}], итог: {подтверждено, частично, не_подтверждено, выдумано, проблем_всего, по_видам: {...}}, худшие_10: [коды с одной строкой сути], вопросы: []}
Ничего не додумывать за Google: если цитаты не дают ответа — «не_подтверждено», не «наверное верно».

САМОПРОВЕРКА скриптом: JSON валиден; каждое ядро темы имеет вердикт; каждая запись слито и каждый спор имеют вердикт; каждый упомянутый E-код существует в извлечение/страницы.
ОТЧЁТ прорабу (кратко, по-русски): цифры итога, худшие 10, вопросы.
