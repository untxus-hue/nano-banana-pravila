  - журнал — JSON-массив записей `{код, поле, было, стало, основание: {вид, ссылка}, решение, почему}`; ссылка на проблему проверки — `<код ядра>#<n>` (n — номер проблемы в `вердикты[код].проблемы`, с 1), на записи проверки — `слияния:<код>` (вердикт не ровно «верно»), `споры:<код>` (все), `не_сведено:<код>` (вердикт «неверно…» / «причина устарела…»); на поперёк — `П-n`, `С-n`, `группа <№>`, `А-n` / `Б-n`; на линию — `Л<n>`;
  - размердж (Л9) — новое ядро в конец темы с кодом `Я-<тема>-<n+1>`, карта_кодов переводит ушедший старый код на новый;
  - уборка по Л2 — ядро уходит в не_сведено с причиной «пример правила <код>», номер остаётся пропуском (без перенумерации, чтобы не ломать ссылки других тем); если на ядро ссылаются другие темы или оно дом группы дублей — не убирается, а получает статус «выведено» и вопрос;
  - новые поля ядра `слой` и `дом` стоят в конце ядра; дом — строго по `дубли_между_темами.json`, при доме в чужой теме — связь «уточняет» на домашнее ядро;
  - вопросы темы — в канонической форме: новые с `из_части: "правка"`, открытые вопросы проверяющего — с `из_части: "проверка"`, снятые на этом шаге — `снят_сшивкой: true`, `чем_снят: "правка: …"`.
- Скрипт формы прораба (перед каждым коммитом): валидный JSON; коды подряд (пропуск — только ядро, убранное по Л2); карта_кодов покрывает все старые коды; E-коды источников и не_сведено сшивки не потеряны, новые E-коды существуют в `извлечение/страницы`; кириллица в английских полях; перечисления (класс, сила, применимость, статус, дата_тип, роль, тип связи, слой, значения моделей); шесть ключей моделей у ядер и в матрице; связи ведут на существующие коды; у каждого ядра слой и дом, дом совпадает с группой дублей и при чужом доме есть связь «уточняет»; ядра `действует: false` имеют `заменено.почему`; блок `споры` = ядра со статусом «спор»; у каждой проблемы проверки и каждого предложения статуса по теме есть запись в журнале.
